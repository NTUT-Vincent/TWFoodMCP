# TWFood MCP 搜尋關鍵字規格

版本：v1.0  
日期：2026-08-07  
目標：高召回優先，先廣泛建立可追溯的台灣食品營養觀測資料，再逐步補齊、驗證與升級。

## 1. 核心原則

1. 只要能辨識「食品／品項」與「來源」，且找到至少一項明確營養數值，就可建立營養資料候選。
2. 不要求一開始就有完整營養標示；熱量、蛋白質、脂肪、碳水、糖、咖啡因、鈉或膳食纖維任一項皆可收。
3. 官方、營養師、媒體、部落格、新聞、社群貼文、圖片菜單皆可作為來源，但必須分級，不混為同等可信度。
4. 同一食品的不同來源、日期、份量或版本可以並存，視為不同觀測；不得自行平均互相衝突的數值。
5. 搜尋與收錄分離：搜尋採高召回，MCP 回答時再依可信度、時效與完整度排序。

## 2. 關鍵字組合模型

每個查詢由下列維度組成：

```text
[對象] + [營養詞] + [內容型態／份量詞] + [情境詞] + [時效詞／來源限制]
```

不必每次使用全部維度。第一輪用 2～3 個維度廣搜，第二輪再加入品項、份量或網站限制精搜。

## 7. 搜尋批次優先級

### P0：最高優先

- 官方商品頁、官方 PDF、食安專區、包裝營養標示。
- 已知品牌 × `營養標示／熱量／完整菜單`。
- 可產生大量結構化列的完整熱量表、全品項文章。

### P1：高需求、高資料量

- 超商鮮食、早餐店、手搖飲、速食、咖啡、便當、鍋貼水餃、壽司、火鍋。
- 量販熟食、冷凍食品、包裝食品。
- 品牌 × 四大營養素；飲料 × 糖量／咖啡因；加工食品 × 鈉。

### P2：補足生活場景

- 台灣小吃、夜市、一般外食、自助餐、無品牌便當。
- `一份／一碗／一顆／一盤` 等常見食用單位。
- 減脂、增肌、高蛋白、低鈉、高纖等情境文章。

### P3：長尾與探索

- 社群貼文、圖片菜單、開箱、新聞、舊文章。
- 地區限定店、期間限定、新品、聯名品項。
- 缺少完整欄位但至少有一項營養數字的來源。

## 8. 收錄門檻

### 8.1 可直接建立資料列

至少具備：

1. 可辨識的食品名或品項描述。
2. 可追溯的來源 URL；若原始來源為圖片，需保留圖片或貼文 URL。
3. 至少一項營養數值與單位。
4. 能描述份量基準；若來源未明示，記為 `unspecified_serving`，不得自行猜測。

### 8.2 僅建立候選來源、不建立營養資料列

- 只有「低卡、高蛋白、推薦」等敘述，沒有任何數值。
- 圖片目前無法清楚辨識，但來源值得日後人工處理。
- 頁面列出品項卻未附營養數據。

### 8.3 排除

- 無法辨識食品或數值對應關係。
- 無 URL、無原圖、無作者／發布帳號，完全無法追溯。
- 搜尋摘要中的數字，打開來源後無法找到。
- 純食譜文章且沒有成品份量及營養數值。
- 明顯為非台灣市場且無法標示市場差異的資料。

## 9. 來源與資料分級

| 等級 | 來源 | 預設狀態 |
|---|---|---|
| A | 台灣官方商品頁、官方 PDF、包裝原始營養標示 | `verified_official` |
| B | 營養師、醫療機構、可信健康媒體，且數值可追溯 | `professionally_transcribed` |
| C | 新聞、媒體、部落格整理，具體列出品項與數值 | `transcribed_unverified` |
| D | Dcard、PTT、Threads、Instagram、Facebook、圖片菜單 | `social_unverified` |
| E | 估算、區間、第三方資料庫、無法確認原始標示 | `estimated_or_historical` |

來源等級只影響排序與回答說明，不作為自動拒收條件。

## 11. 去重與版本規則

建議觀測鍵：

```text
canonical_source_url + brand_or_context + food_name_normalized + serving_basis_normalized
```

- 同一鍵、相同數值：略過或更新擷取日期。
- 同一鍵、數值改變：建立新版本或觀測紀錄，保留舊值與觀測日期。
- 不同來源的同品項：全部保留，供後續比較與驗證。
- 不同市場、杯型、甜度、冰量、加料、套餐：分開記錄。
- 區間值保留原始上下限，不自行取平均。

## 12. 查詢生成策略

避免把所有詞做笛卡兒積而產生大量低價值搜尋。每個對象依序執行：

1. `{對象} + 營養標示／熱量`。
2. `{對象} + 四大營養素`；飲品加糖量／咖啡因，加工品加鈉。
3. `{對象} + 菜單／全品項／圖鑑／懶人包`。
4. `{對象} + 具體份量詞`。
5. `{對象} + 情境詞`。
6. 官方資料不足時，才擴至媒體、部落格、社群與圖片搜尋。
7. 每輪加入 `2026／2025／最新／新品`，另開歷史輪次，不讓舊資料覆蓋現行值。

## 13. MCP 回答排序建議

回答同一食品時依序考量：

1. 市場與品項吻合。
2. 份量完全吻合。
3. A → B → C → D → E。
4. 新資料優先，但不得無聲覆蓋舊版本。
5. 完整營養標示優先於單一熱量值。
6. 若來源互相衝突，並列呈現差異、來源與日期，不自行裁定或平均。
